# September multiplayer playtest fixes

Work branch: `fix/multiplayer-playtest`, based on `3fa92dc`. The original
multiplayer checkout and remote four-player work were not edited.

## Why the behavior differed

The host should execute both players' semantic actions through Fallout's normal
rules. The guest should play those actions visually and apply the host's results.
Running the full action twice would repeat scripts and random damage rolls.

The branch already routes commands through an authority, but several engine
assumptions remained. Inventory temporarily detached held items while a modal
window was open; turn setup read a shared critter template without selecting the
player's build; replica snapshots cancelled moving animations; and attack events
were accepted without showing an attack. These are integration defects, not
intended multiplayer rules.

## Changes

- Preserve the earlier attacker-pointer fix. The snapshot code no longer writes
  an integer into the same union storage after assigning `whoHitMe`.
- Stop idle replica animation drift and clear accumulated sprite offsets. Keep
  nearby exploration paths running through intermediate checkpoints. Refresh
  old and new sprite bounds when their presentation changes, and avoid repainting
  unchanged scenery at every checkpoint.
- Resize replica map-local variables in both directions. Rat script removal can
  compact the host's array from two entries to zero; the guest previously rejected
  every subsequent checkpoint. Only host checkpoints compact replica locals.
- Display native end-turn buttons and the owner's AP on the guest. Turn setup
  selects the player's actual build before reading AP and perks.
- Keep the original inventory art, slots and drag controls. Render held items
  from a filtered inventory view without detaching real objects on the replica.
  Host equipment commands validate ownership and turn revision, split stacked
  items when necessary, update armor and weapon art, and retain the chosen loadout.
  Inventory access costs its native AP amount once per opening; changing hands is
  free. No separate multiplayer equipment screen remains.
- Permit native inventory and hand controls in combat. Use the native aimed-shot
  picker, the local player's accuracy display, and the command's called-shot AP
  cost rather than the host HUD's current selection.
- Play a player's native weapon attack art on the guest before applying its
  result checkpoint. This presentation never calls `combat_attack`, damage,
  scripts or random rolls. It has a three-second upper bound and finishes before
  checkpoint acknowledgement. Death and damage still come from the host.
- Give a new peer the initial inventory when starting a fresh game. Recovery
  restores its saved inventory instead of seeding another kit.
- Use SDL desktop fullscreen so quitting or killing the game does not leave the
  physical monitor in a 640x480 display mode.
- Journal explicit equipped slots, ammo, combat owner and turn revision. Add
  `game_equip` for controllers through the same host command path.

Gameplay wire version is 31. Both machines need the matching build before the
next multiplayer session.

## Validation

`ctest --test-dir build --output-on-failure` passes all three suites. Equipment
coverage includes ownership rejection, stale phases/turn revisions, malformed
messages, replay protection, and inventory open/close serialization.

Installed-data tests run a real host and guest on separate virtual displays.
Native UI tests drag a knife into a hand, back into the list, and into the hand
again on each player while checkpoints continue. The host starts with two knives;
one remains in the inventory and one stays equipped after combat. They then execute both players'
weapon attacks and compare final state digests. The combat fixture also checks
that opening inventory charges four AP once and multiple edits do not charge
again. Other scenarios cover aimed pistol attacks, script-local compaction after
a rat death, reload, item consumption, authenticated reconnect/recovery, movement,
and a knife trade with nothing requested in return.

Run the native UI regression with:

```sh
python3 tools/test_native_multiplayer_inventory.py build/fallout-ce /path/to/game-data
```

It needs `xvfb-run`, `xdotool` and ImageMagick `import`. It preserves logs,
journals and before/after screenshots in the printed temporary directory.

## Still requires work

The physical HAL display has not been retested with these changes. No measured
FPS claim is supported. NPC combat movement and reactions are still largely
checkpoint-driven; player attack art alone does not reproduce the full native
combat sequence, sounds, projectiles and death reactions. Those need explicit
presentation events from the host and a presentation state separate from the
state used for gameplay checksums.

Native inventory container navigation and unloading are not yet routed through
host commands; the network inventory reports them unavailable. Ammo dragging and
all inventory context actions need a separate parity pass. The shared engine
also contains other `obj_dude` assumptions outside the corrected turn and HUD
paths. Passing the listed tests does not establish full single-player parity.
